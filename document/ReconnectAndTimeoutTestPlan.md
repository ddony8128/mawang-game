## 재접속 / 새로고침 / 핑 타임아웃 테스트 플랜

### 1. 기본 재접속 플로우

- **시나리오 1-1: 메인 진입 시 재접속 버튼 노출**
  - 선행 조건: 이전 세션에서 어떤 방에 입장한 상태로 브라우저를 닫았고, `room_players.device_id` 가 저장되어 있음.
  - 단계:
    1. 브라우저를 새로 열고 `/` 진입.
    2. `POST /api/auth` 가 호출되고, 서버가 `reconnect.available=true`, `roomId`, `phase` 를 내려주는지 확인.
    3. 메인 화면 상단에 “\<roomTitle\> 재접속” 버튼이 노출되는지 확인.
  - 기대 결과:
    - 방이 `phase=lobby` 면 `/room/:roomId/lobby` 로 이동.
    - 방이 `phase=game` 면 `/room/:roomId/game` 으로 이동 후 WS `ready` 전송.

- **시나리오 1-2: 재접속 버튼 클릭 후 게임 화면 복구**
  - 선행 조건: 위 시나리오 1-1 후 “재접속” 버튼이 보이는 상태.
  - 단계:
    1. “재접속” 버튼 클릭.
    2. 게임 화면(`/room/:roomId/game`) 진입 후 WS 연결 및 `ready` 전송.
    3. 서버에서 `snapshot` 수신 후 인게임 UI가 정상적으로 렌더링되는지 확인.
  - 기대 결과:
    - 손패/HP/플레이어 리스트 등이 서버 상태와 일치.
    - UI 상 이벤트 로그/알림 모달도 최신 상태를 반영.

### 2. 인게임 중 새로고침

- **시나리오 2-1: 게임 화면에서 브라우저 새로고침**
  - 선행 조건: `/room/:roomId/game` 에서 게임 진행 중.
  - 단계:
    1. F5 또는 브라우저 새로고침 버튼 클릭.
    2. 앱이 다시 로드되면서 `/` → `/room/:roomId/game` 경로로 재진입(라우터 정책에 따라).
    3. WS 연결 및 `ready` 전송.
  - 기대 결과:
    - 서버에서 동일 플레이어의 세션을 검증하고, `snapshot` 을 다시 내려준다.
    - 새로고침 전과 동일한 HP/손패/효과/로그 상태로 복구.

### 3. 핑 타임아웃(미응답) 강제 사망

- **시나리오 3-1: 클라에서 인위적으로 pong 중단**
  - 선행 조건: 게임 진행 중, 여러 플레이어 접속.
  - 단계:
    1. 특정 플레이어 클라이언트에서 네트워크를 끊거나, 디버그 도구로 WS pong 응답을 막는다.
    2. 서버가 주기적으로 ping 을 보내는지 로깅 또는 네트워크 탭으로 확인.
    3. 약 5분(예: missCount>=10) 이 경과할 때까지 대기.
  - 기대 결과:
    - 해당 플레이어에 대해 엔진에 `SYSTEM_TASK(FORCE_DEAD_BY_TIMEOUT)` 가 enqueue 된다.
    - Engine 이 HP=0, alive=false 로 처리하고 delta 를 통해 patch 를 생성.
    - 남아 있는 클라이언트들은 해당 플레이어가 사망 상태로 표시되는지 확인.

- **시나리오 3-2: 타임아웃 사망 후 게임 종료 조건 체크**
  - 선행 조건: 마왕 또는 모든 용사가 타임아웃으로 사망할 수 있는 상황.
  - 단계:
    1. 마왕 클라이언트의 pong 을 막아 타임아웃 사망을 유도.
    2. 또는 용사 전원을 타임아웃 시켜본다.
  - 기대 결과:
    - 마왕 최종 사망 시 `GameEndState(reason=\"MAWANG_DEAD\")` 가 생성되고 WS `end` 가 전송.
    - 용사 전원 사망 시 `GameEndState(reason=\"ALL_HERO_DEAD\")` 및 WS `end`.
    - 각 클라에서 결과 모달/역할 공개 모달을 거쳐 로비 또는 메인으로 되돌아가는 플로우가 정상 동작.

### 4. 방 삭제 / GAME_ABORTED 처리

- **시나리오 4-1: 방장이 게임 중 방 삭제**
  - 선행 조건: 게임 진행 중, 방장과 여러 플레이어 접속.
  - 단계:
    1. 서버 관리 도구 또는 추후 구현될 방 삭제 기능으로 해당 방을 삭제 처리.
    2. 인게임 클라이언트가 WS `error(code=GAME_ABORTED, next=go_lobby)` 또는 REST 폴링에서 에러를 받는지 확인.
  - 기대 결과:
    - 모든 플레이어가 인게임에서 빠져나가 메인 또는 로비로 이동.
    - 재접속 버튼(`reconnect.available`)은 false 로 초기화되거나, 더 이상 해당 방을 가리키지 않는다.
